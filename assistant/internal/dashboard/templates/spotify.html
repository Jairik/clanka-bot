Dashboard

Spotify

Two separate grants. Connect pairing lets librespot play music through the Assistant's Pulse sink; its credentials are cached on librespot's own volume. Web API auth is an OAuth refresh token in the write-only secrets table, used only for control. This page shows metadata, never a token.

Pair a phone or desktop

  1. Put the phone or desktop on the same LAN as the Pi. Spotify Connect discovery is mDNS, so it does not cross a Docker bridge network; librespot runs with host networking for this reason.
  2. Play something in Spotify, open Devices, and choose {{if .Pairing.Device}}{{.Pairing.Device}}{{else}}Clanka{{end}}.
  3. The first connection writes credentials.json to librespot's own librespot-cache volume. Later starts reuse it; the Assistant never mounts that volume.

If the device does not appear, confirm UDP 5353 and the configured zeroconf port are allowed on the LAN, and set SPOTIFY_ZEROCONF_INTERFACE to the Pi's LAN address when the host has more than one interface.

Register the app first

Set these in .env (or config.yaml) and restart the assistant:

SPOTIFY_CLIENT_ID=<your app's client ID>
SPOTIFY_REDIRECT_URI=https://<pi-name>.<tailnet>.ts.net/spotify/callback

Create the app in the Spotify Developer Dashboard, add the exact redirect URI to its allowlist, and keep it in development mode. Development mode is limited to five authenticated users; the app owner needs Spotify Premium.

{{else if not .WebAPI.RedirectConfigured}}

The client ID is configured but the redirect URI is not. Set spotify.redirect_uri to the exact callback URL and restart.

{{else}}

Redirect URI

This exact value must be in the Spotify app's Redirect URIs allowlist, including the scheme, host, port and path. Spotify requires HTTPS except for a loopback IP literal, and does not accept localhost.
